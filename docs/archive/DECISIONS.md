## D-011：第二段视频作为冻结参数 holdout

- 日期：2026-08-08
- 状态：已完成
- 决策：`vid_a598228fbc11` 使用固定的 `hit-rules-0.3.0`（阈值0.38、最小间隔0.4秒、回合间隔6秒）先完成机器运行；人工只在隐藏候选帧的 `/gold` 中独立标注。
- 约束：Gold 锁定后只运行一次正式评估，不在该视频上修改参数；若结果不足，将原因带到未来开发集，不能把本 holdout 继续当调参集。
- 标定：四个抽查帧确认机位和球场像素位置与首段视频一致，因此复用四角几何，但为新视频保存独立 calibration ID 和来源记录。
- 已知偏差：人工标注前曾披露机器候选总数，但没有披露候选帧、击球者或置信度；本份数据记为 frame-blind holdout，而非完全信息盲测。
- 结果：64条Gold对79条冻结候选，主稳健窗口下Precision 74.68%、Recall 92.19%、F1 82.52%；参数没有在Gold锁定后修改。
- 结论：击球存在性F1复现开发视频，但击球者准确率仅64.41%、中位时序偏移为-6帧，因此v0.3只被接受为候选生成基线。

- 约束：v0.4不得在旧holdout上重跑或以其结果继续修改；晋升需要新验证视频。

## D-015：轨迹异常采用击球感知的软门控，不用固定跳变阈值硬删

- 日期：2026-08-09
- 状态：开发版已实现，待新视频验收
- 现状：alpha-beta滤波会平滑检测并外推最多5帧缺失点，但每帧只保留最高置信度球框，且没有基于预测创新残差的异常值门控。
- 风险：击球候选的轨迹分数依赖相邻三帧方向和速度变化，并占事件置信度52%；错误跳点可能产生伪变向，同时污染后续速度预测和比赛状态运动证据。
- 证据：开发视频原始相邻检测最大跳变约433像素，平滑后仍约266像素；最大跳变附近既有真实击球也有误报，因此固定速度/位移阈值会同时删除真击球。
- 决策：保存top-k检测并做时序关联；输出创新残差、轨迹不确定度、测量状态和权重。连续性与检测置信度决定基础权重，手腕/姿态证据提供真实击球急变向的软权重下限。接触判定使用被接受的关联检测点，轨迹曲率仍使用平滑点。
- 插值：本版明确`interpolation_applied=false`。缺失点只保留原有最多5帧因果速度外推，不做线性、样条或双向插值；是否加入需另行评估。
- 开发结果：153帧含多候选，20帧选择非首候选，45帧软抑制；轨迹位移P99从157.13降至87.84像素，最大值从265.69降至173.26像素。稳健击球F1从82.54%升至83.20%，击球者准确率保持86.54%。
- 约束：版本标记为`shuttle-track-0.2.0-dev`和`hit-rules-0.5.0-dev`，不得直接晋升；旧holdout与validation原产物保持原哈希且不得覆盖。D-016后来允许冻结参数后写入独立目录做回顾性安全审计，但不把它作为前瞻晋升成绩。

## D-016：比赛进行状态采用序列/机理门控，并保留全部被抑制候选

- 日期：2026-08-10
- 状态：开发版已实现，待新盲标视频前瞻验收
- 决策：不采用单一`play_state_score`阈值，也不使用Gold首尾帧裁剪。候选先完整生成；只有序列支持达到0.75的候选，才能通过0.25–4秒内的交替击球者关系和连续球追踪/运动证据建立active-play区间。
- 边界：active-play区间向前保留0.15秒、向后保留0.35秒，降低首末次击球被切掉的风险；区间外逐帧标记为`inactive_wait`，其候选不进入最终事件表。
- 可恢复性：`events.provisional.jsonl`保存门控前全部候选，`events.jsonl`保存最终候选，`events.suppressed.jsonl`保存区间外候选及门控原因；门控可通过`--play-state-gate-mode off`关闭并无损回到v0.5规则。
- 依据：开发集67→66条，抑制1个误报且稳健召回不变；冻结参数后在旧validation做回顾性审计，58→55条，抑制3个误报且召回不变；旧holdout 76→76条，门控无影响。
- 限制：旧validation/holdout已经存在Gold，因此上述结果只证明回顾安全性，不构成前瞻泛化验收。短回合、候选稀疏或首末击球漏检时，序列门控仍可能误杀真实候选；晋升必须使用包含多个回合与明显等待阶段的新盲标视频。
- 版本：`play-state-gate-0.1.0-dev`、`hit-rules-0.6.0-dev`。原锁定事件与Gold文件未覆盖，哈希保持不变。
