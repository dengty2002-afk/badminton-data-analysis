# MonoTrack HitNet 隔离对照实验

日期：2026-09-13。结论：当前本地复现版不应替换生产击球检测器。

**本次完成的是官方架构的本地训练实验；官方预训练权重测试尚未完成。** 没有找到官方 HDF5 权重，不能将下列数字称为原作者模型成绩，也不能据此判定 MonoTrack 方法本身无效。

## 实验设置

- 官方源码固定提交：`39e9227bd44fa2a579731b1cc97c7f529f391cd6`。
- 12 帧 × 78 维；两层双向 GRU，每方向 64 单元；全局最大池化；3 类输出。
- PyTorch 架构复现，未加载 TensorFlow 官方权重；使用现有 CUDA 环境，未安装依赖。
- 复用当前 RTMPose、YOLO11s 和轨迹平滑结果，测试的是 HitNet 接入现有特征后的效果；未复现 MonoTrack 整套视觉前端。
- 训练：2 段视频 / 122 个人工击球；验证：1 段 / 41 拍；测试：6 段 / 174 拍。
- 按视频分开但机位相同；这是历史数据回顾性比较，非新的前瞻盲测或跨比赛泛化验证。
- 3 个随机种子，各 80 轮；按验证窗口 macro-F1 选每次训练的权重。全部测试成绩均列出，不按测试结果挑种子。
- DP 和 naive 均调用从官方源码原样提取的方法。温度为 1；无测试集阈值校准、时间平移或截掉首尾误报。
- 主指标：±5 帧加每条 Gold 声明的不确定度；辅助指标再加 6 帧反应余量。

## 诊断与解释

- 严格 F1 从现有规则的 67.72% 降为 37.15%～41.24%，不适合直接作为更好的 BST 切片前置。
- 宽松 F1 为 74.81%～78.31%，现有规则为 78.22%；没有稳定增益。
- 宽松匹配的时间绝对误差中位数：现有规则 3 帧，HitNet 为 6、6、7 帧；有符号中位误差分别为 +5、+5、+4 帧，说明定位偏晚。未用这些测试偏移纠正预测。
- HitNet 对匹配事件的击球侧准确率更高，但各方法匹配事件不同，不能把该条件指标单独当作整体优越性。
- 原版 DP 限制至少约半秒间隔、双方交替和约每秒 1.2 拍总数；这些先验可能限制快节奏片段，本次没有改动它们。
- 原版 naive 后处理严格 F1 为 13.62%～21.85%，宽松 F1 为 40.00%～46.22%，召回率很低；完整数字见 summary.json。
- 本地训练只有 122 拍；标注包含人工反应不确定度，输入视觉模型和官方不同，原版网络/标签窗口又以帧计。结果只支持拒绝当前候选替换，不支持否定更大数据训练后的 HitNet。

## 对 BST 的处理

已单独导出每种预测的 `bst-windows.jsonl`，采用作者 previous-hit → next-hit+extension 及最大时长规则，不导出小视频，不修改生产适配器。回合边界仅采用 6 秒自动间隔启发式，不使用 Gold。当前没有球种真值，因此本实验不报告 BST precision/recall，也不宣称切片改变已提高球种准确率。

## 隔离与复现

- 实验目录：`<PROJECT_ROOT>\experiments\monotrack-hitnet`。所有新增源码、权重、预测、指标均在此目录。
- 对 75 个生产源码、BST 文件、输入特征、标定、Gold 和基线预测作前后 SHA-256 检查，变更数为 0。
- 未修改前端、未启动标注界面、未改写历史评估、未安装新的运行依赖。
- 原始方案与偏差见 PROTOCOL.md；网络接口测试见 test_contract.py；原始评估含每个 TP/FP/FN 的帧号。
- 官方源码采用 Adobe Research License；保留原许可于 upstream/LICENSE。

从项目根目录运行：

```powershell
.\.venv-model\Scripts\python.exe -B experiments/monotrack-hitnet/run_experiment.py --output experiments/monotrack-hitnet/results-new
```

已有结果不能覆盖；重跑必须指定新目录。继续开发应使用新验证数据，避免根据这六段测试成绩反复调参。

## 下一步决定

保留现有生产检测器。若继续走 MonoTrack 路线，应获取有来源的官方权重，或按比赛划分用更大规模 ShuttleSet 击球标签训练，再检验原版 DP 的时序限制。本轮不继续扩展前端、数据标注管线，也不把本地实验权重晋升为默认模型。

参考：[MonoTrack 官方仓库](https://github.com/jhwang7628/monotrack)，[官方权重请求](https://github.com/jhwang7628/monotrack/issues/3)。
