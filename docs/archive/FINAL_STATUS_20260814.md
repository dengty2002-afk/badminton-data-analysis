# ShuttleLab 本地数据管线最终状态（2026-08-14）

## 结论

工程版本已经形成可批量续跑、可审计、可分享的自动 ShuttleSet-like **预标注**管线。
它能从固定机位和标准转播主视角视频中生成姿态、球轨迹、球员米制位置、场地边界、击球候选、
17 类基础球种预测和目的地代理值，并输出 Parquet/CSV/JSONL。它还不能被科学地称为“带准确
球种、落点的真值数据集”，因为项目内没有球种/落点 Gold 用于本域评估。

## 本轮完成

- 接入上游 BST `seq100 fine35 serial2` 权重，复现其姿态骨架和球坐标预处理。
- 保存球种原始类别、Top-3、模型置信度、输入质量、预测状态、来源与人工复核状态。
- 正常拍目的地采用下次触球观测与接球方米制位置融合；越界结果拒绝输出。
- 终局拍新增保守轨迹终止估计，仅在终止证据充分时输出低置信度实验值，否则为空。
- 转播视频主视角采用源帧清单，不复制原始视频；跨片段时重置球轨迹，避免假跳变。
- 批处理阶段统一为注册、主视角、场地、推理、校验、合并，支持失败续跑和单视频状态。
- 数据质量报告明确区分自动覆盖率和 Gold 准确率，并警告未确认的语义预标注。
- 上游模型指标纠正为当前权重对应的 Accuracy 0.760、Macro-F1 0.691、Top-2 0.930；这些是
  上游 ShuttleSet 测试成绩，不是本项目视频的成绩。

## 验证证据

- 单元测试：68/68 通过。
- 完整便携性验证：模型哈希、依赖、导入和测试均通过（见最终交付报告）。
- 真实转播视频 300 帧 CUDA 端到端：14.633 秒，推理 25.032 fps；两名球员轨迹覆盖率
  96.3%/100%，球轨迹覆盖率 95.7%；13 个临时候选经比赛状态门控保留 11 个、抑制 2 个；
  11 个球种预测，9 个正常拍目的地、1 个实验终局落点、1 个越界拒绝。
- 该片段球种非 unknown 覆盖率 54.5%，语义 Gold 确认覆盖率 0%。这正是当前版本不能宣称
  “准确真值”的关键证据。

## 素材与容量

- `uncensored_videos`：29 个 MP4，28.80 小时，16.06 GiB。
- `.venv-model`：3.59 GiB；`demo`：0.65 GiB；`data`：约 0.49 GiB。
- 主视角清单不复制视频，避免额外产生约 16 GiB；完整批量推理会显著增加逐帧 JSONL。
- 当前 GPU 实测约 25 fps，29 段素材理论推理约 30.6 小时，未计主视角扫描、标定和 I/O。
  CPU 实测仅约 1.34 fps，理论约 571 小时，不适合全量运行。

## 未解决且需要产品决定

1. 是否接受“自动预标注 + 抽检”的交付定义；若必须叫真值，则必须投入语义人工 Gold。
2. 是否新增缺失的官方第 18 类 `driven flight`；现有上游 BST 无此输出，需要新数据与训练。
3. ShuttleSet 目的地究竟要“下一次触球位置代理”还是严格“球落地位置”。单目 Homography 对
   空中球存在高度偏差；严格落点需要专门 Gold、轨迹/时序模型，最好有更高帧率或多视角。
4. 自动主视角自适应阈值在画面长期相似时可能过选；当前真实视频本身 99.64% 都像主视角，
   下游场地和比赛状态门控能降风险，但全量前仍建议抽查每段预览。

## 版本判定

- 工程成熟度：候选发布版（可批处理、可恢复、可复现、可分享）。
- 几何/轨迹输出：适合分析和人工复核，尚无逐项本域误差基准。
- 击球帧：已有含时间容差的 Gold 评估链路。
- 球种/目的地：预标注阶段，不是科学真值；这是数据缺口，不是隐藏的软件错误。
